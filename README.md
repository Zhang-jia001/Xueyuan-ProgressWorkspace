## 每周更新：3 步

1. **把新导出的表丢进 `学员数据/`**
   文件名以日期开头，例如 `261105-四部数据.xlsx`（26 年 11 月 5 日）。同一天拆成多张表（按团队 / 学校分批导出）也没问题，会自动合并。
2. **跑一次构建**
   ```bash
   python3 .workbuddy/build/build.py --anon
   ```
3. **双击 `学员学习进度台.html`** 就是最新数据。

脚本会自动做这些事，**不用删旧表、不用改代码**：

- 挑出日期最新的那批表（同日多表合并），更旧的表自动忽略并打印提示
- 数据快照日 = 文件名日期，页头、计划表、曲线全部跟着走
- 按**表头名**取列，导出表列的增减 / 顺序变化不影响（2026-10 起的新 15 列格式与之前的 13 列格式都兼容）
- 同一个人出现在多张表里，按手机号去重、后读的覆盖前读的

> `--anon` 会顺带重生成脱敏版 `index.html`，并在末尾打印脱敏校验结果（应为「干净，0 处泄漏」）。只更新本地版可去掉该参数。

## 它解决什么问题

课程运营通常只看到平台后台一个「完成度 X%」。这个数字无法直接支撑行动——不知道他卡在哪一章、按现在速度何时学完、更看不出「学得慢」到底是**没来**还是**学不会**。

四条链路：

| 链路 | 输入 | 输出 |
|---|---|---|
| 进度 → 章节 | 完成度 %、平台「当前学习章节」、最后提交的作业 | 定位到 233 章中的哪一章，冲突时标「待校准」 |
| 投入 → 毕业周期 | 累计时长、开通天数、每周实际投入 | 学完需要几周、哪个情景能压进一年 |
| 行为 → 干预优先级 | 静默天数、窗口占用、每课时耗时 | P0–P3 分级 + 可直接照做的动作 |
| 情景 → 曲线 | 投入强度、习惯爬坡、疲劳衰减 | 三档情景下 52 周进度曲线 |

## 核心算法

### 1. 进度百分比 → 精确章节

```
已学课时 = 完成度% × 1357（课程总课时）
```

已学课时落入按顺序累加的章节课时区间 → 推算章节。再与平台导出的「当前学习章节」「最后一次提交的作业」三方交叉校验：

| 置信度 | 判据 |
|---|---|
| 高 | 页面章节位置与进度相差 ≤6 个百分点 |
| 中 | 相差 ≤15 个百分点 |
| 低（显示「待校准」） | 相差 >15 个百分点，或页面章节无法识别 |

**冲突时一律以进度为准**，因为平台进度是所有模型指标的共同输入；页面章节仅作参考，抽屉里会单独列出「平台记录当前章节：第 N 章 …（与进度差 X 个百分点）」。这类冲突通常是学员回头翻旧章节，或是刷课导致进度虚高。

> 章序已归一化为连续 1–233：平台源数据的 S6 段章序从 10003 起跳，直接使用会让「下一章」「差几章」错位。

### 2. 学习曲线推演（预测层）

```
每周推进课时 = 投入强度 × 习惯爬坡(w) × 疲劳衰减(P)

习惯爬坡  habit(w)   = 1 - exp(-(w+1) / 2.5)      # 前 2–3 周进入状态慢
疲劳衰减  fatigue(P) = 1 - 0.45 × (P/100)^1.5     # 进度越靠后越慢
投入强度  wk         = 每周实际投入小时 × 学习效率（课时/小时，钳制 1.0–2.6）
```

| 情景 | 投入假设 |
|---|---|
| 坐满窗口 | 每周至少 12 小时（院校晚自习 19:00–21:00 × 6 天，周日休息） |
| 维持现状 | 按当前实际每周投入 |
| 投入回落三成 | 当前投入 × 0.7 |

内部推演 156 周（3 年），图表只采样前 52 周（每 4 周一点）。这样「一年内学不完」的学员也能给出真实年限，而不是空值。

### 3. 断学风险 → 撑到毕业的概率

```
周中断率 h = 0.5% + 2.5% × (静默天数 - 1) + 1.5% × (75 - 窗口占用%) / 75
          （上限 35%）

撑到毕业概率 = (1 - h) ^ 需学完的周数
```

基础值 0.5% 来自实际数据校准。静默越久、晚自习越空，中断风险越高。

### 4. 干预优先级与动作分流

优先级只回答一个问题：**要不要打电话**。

| 级别 | 判据 |
|---|---|
| P0 | 断学 ≥ 7 天 |
| P1 | 每周投入不足窗口一半 / 每课时耗时达标准 1.5 倍 / 观察期内断学 4 天 |
| P2 | 出勤未满 75% / 超出一年线 / 观察期内已出现刷课信号 |
| P3 | 正常，不需要干预 |

动作按**问题类型**分流，因为「没来」和「学不会」的解法完全相反：

| 类型 | 判据 | 动作 |
|---|---|---|
| 出勤不足 | 窗口占用 < 60%，每课时耗时正常 | 先不谈学什么，要求每晚坐满 2 小时 × 5 天 |
| 效率卡点 | 每课时耗时 ≥ 0.72h（标准 0.48h 的 1.5 倍） | 不再加时间，共享屏幕陪跑一章查卡点 |
| 问题叠加 | 两者同时成立 | 一次只解决一个，先出勤、后效率 |
| 进度存疑 | 已学 ≥ 30 课时且每课时 < 0.25h | 抽查最近 3 章作业，讲不出代码就作废进度重学 |

「进度存疑」设了 30 课时门槛：刚学 20 多课时的新生每课时耗时必然偏低，不构成刷课证据。

## 页面功能

- **顶部 KPI**：在读人数、平均完成度、累计时长、近 3 日活跃率、本周待干预、毕业周期中位数
- **预测带**：三档情景下各有多少人能在一年内学完
- **段位分布 / 模块聚集 / 班级进度**：看整体卡在哪个模块、哪个班掉队
- **学员明细表**：按团队 / 班主任 / 学校 / 段位 / 优先级筛选，点行看详情
- **学员详情抽屉**：当前位置（含章节冲突提示）、段位路径、投入指标、52 周曲线（SVG）、周任务
- **干预清单**：按优先级排序，每人配一条具体动作
- **个人学习计划书**：可打印 / 存 PDF（四周边界任务 + 段位里程碑）
- **学员录入**：13 字段表单，实时预览定位到哪一章、哪天学完，可编辑、可导出 CSV 回灌

## 技术说明

- **单文件交付**：数据、样式、脚本全部内联，无外部依赖、无网络请求
- **图表手绘**：预测曲线用原生 SVG，未引入图表库
- **前后端同构**：构建脚本（Python）与页面内 `compute()`（JS）实现同一套算法，逐字段一致，由一致性测试守护（曲线逐点容差 0.5 个百分点——两侧 `pow` 末位差异会在 40 周推演中累积，实测最大 0.30，业务无意义；毕业周按 ±1 周校验）
- **舍入口径**：统一 half-up（`floor(x*n+0.5)/n`），避免 Python 银行家舍入与 JS `Math.round` 在 `.5` 边界相差 0.1
- **脱敏靠重渲染而非替换**：先把数据里的姓名 / 手机号 / 团队 / 班主任 / 班级编号化，再用同一模板渲染，不存在漏改字段；生成后自动比对原始姓名与手机号，实测 0 处残留
- **本地优先**：录入数据存 `localStorage`，可导出 CSV 回灌构建流程，不依赖任何后端
